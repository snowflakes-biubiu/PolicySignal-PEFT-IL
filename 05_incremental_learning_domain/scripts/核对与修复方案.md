```python
import re, unicodedata

def text_key(text: str) -> str:
    s = unicodedata.normalize("NFKC", str(text)).casefold()
    s = re.sub(r"[^\w\u4e00-\u9fff]", "", s)
    return hashlib.sha256(s.encode("utf-8")).hexdigest()[:20]

ERA_ALL = {"T1_1949_1978", "T2_1979_1992", "T3_1993_2002",
           "T4_2003_2012", "T5_2013_2023"}

def validate_all_temporal_data():
    datasets = {t: validate_task_data(t) for t in TASKS}
    seen_text: dict[str, str] = {}                  # 全库唯一（含同 location）
    doc_locations: dict[str, set[str]] = defaultdict(set)
    overlap_docs = 0
    for task, splits in datasets.items():
        expect_domain = TASKS[task].get("domain")
        eras = Counter()
        for split, records in splits.items():
            location = f"{TASKS[task]['name']}/{split}"
            for r in records:
                if expect_domain and str(r.get("domain", "")).strip() != expect_domain:
                    raise ValueError(f"{location} 存在错域记录: {r.get('domain')!r}")
                k = text_key(r["text"])
                if k in seen_text:
                    raise ValueError(f"段落重复: {seen_text[k]} 与 {location}")
                seen_text[k] = location
                eras[str(r.get("era"))] += 1
                doc_locations[str(r.get("DocumentID"))].add(location)
        if ERA_ALL - set(eras):
            raise ValueError(f"{TASKS[task]['name']} 缺少年代: {sorted(ERA_ALL - set(eras))}")
    overlap_docs = sum(1 for locs in doc_locations.values() if len(locs) > 1)
    print(f"文档跨(任务/划分) {overlap_docs} 篇（A3 允许，仅留痕）")
    return datasets
```

- `DOCUMENT_EXCLUSIVE=False` 时**仍然**统计文档重叠，只写报告不报错。
- 修 `:375-376` 文案为「类别均衡、年份合法、段落全局唯一、文档重叠 N 篇（A3 允许）」。

## 2. P1-2 头尾截断：正文头部几乎被丢

### 2.1 核对证据（实测）

| 项 | 实测值 |
|---|---|
| `SYSTEM_PROMPT` 纯文本 token | **341**（547 字符 / 401 汉字） |
| system + user 模板前缀 token | **355** |
| head 预算（`767 × 0.5`） | **383** |
| **触发截断后正文头部剩余** | **383 − 355 = 28 token** |
| prompt 长度 min / median / p95 / max | 372 / 437 / 633 / **1032** |
| 触发截断样本 | **36 / 5,400 = 0.7%** |

分布：D1_train 6、D2_train 2、D2_test 1、D3_train 3、D3_test 2、D4_train 3、D4_test 7、D5_train 4、D5_test 3、D6_train 3、D6_test 2。

代码：`truncate_head_tail`（`incremental_common.py:279-298`），`head = int(budget * head_ratio)`，默认 `head_ratio=0.5`；训练与评估同函数（`:340`、`incremental_evaluation.py:416`）。

**判定**：原文"可能吃掉系统提示词"**不成立**；"退化成只保留尾部"**成立**。

### 2.2 影响

- 36 条（0.7%）最长段落输入失真，属"信息量最大"的那批。
- 训练/评估用同一函数，无 train/eval 不一致问题，但与"保留发文机关/标题"的设计注释矛盾。
- 对 84 组指标影响很小，但可解释性上会被审稿人追问。

### 2.3 修复方案

**方案 A（推荐）：文本级截断，提示词永远完整**

```python
_PREFIX_TOKENS: dict[int, int] = {}

def prompt_prefix_len(tokenizer) -> int:
    key = id(tokenizer)
    if key not in _PREFIX_TOKENS:
        _PREFIX_TOKENS[key] = len(build_prompt(tokenizer, ""))
    return _PREFIX_TOKENS[key]

def fit_text(tokenizer, text: str, budget: int) -> tuple[str, bool]:
    """文本层截断：头 60% / 尾 40%，system prompt 不受影响。"""
    ids = tokenizer(text, add_special_tokens=False)["input_ids"]
    if len(ids) <= budget:
        return text, False
    head = int(budget * 0.6)
    tail = budget - head
    left = tokenizer.decode(ids[:head], skip_special_tokens=True)
    right = tokenizer.decode(ids[-tail:], skip_special_tokens=True)
    return left + "……" + right, True
```

调用点：`build_prompt(tokenizer, fit_text(tokenizer, r["text"], MAX_LENGTH - 1 - prompt_prefix_len(tokenizer))[0])`，把 `truncated` 计入 `training_metadata.json` 与评估报告的 `truncation_stats`（`:301` 已有函数可直接复用）。

**方案 B（最小改动）**：`truncate_head_tail` 增加 `reserved_prefix` 参数，head 从 `reserved_prefix + 正文头` 起算。

```bash

# 期望：截断条数 ≤40；training_metadata 里 truncation_rate 有值
```

## 3. P1-3 EWC `param` 归一化随 anchor 数线性增长

### 3.1 核对证据

```python
# continual_training.py:573-589
for state in ewc_states:
    ...
    total = total + state_total                    # 所有 anchor 求和
if normalize == "param" and per_state_param_count:
    total = total / per_state_param_count          # 只除「单套」参数量
elif normalize == "task":
    total = total / max(1, len(ewc_states))        # 只除套数，不除参数量
```

- `param` 模式：T2 有 2 套 anchor（启动时先估 T1，再追加 T2）→ 系数 `2/P`；T6 有 6 套 → `6/P`。**同等 Fisher 下 T6 惩罚是 T2 的 3 倍**，而 λ 全局固定 100。
- 文档字符串 `:559` 写"与任务数无关"，与实现矛盾。
- `task` 模式：系数 `1/n`，未除 `P`，量级约为 `param` 模式的 `P` 倍。
- 损失合成 `loss = ce + (λ/2) × penalty`（`:804`），日志只记合并 loss（`:773-778`），无法分离。

### 3.2 LoRA 参数量（解析计算）

`TARGET_MODULES = ["q_proj","k_proj","v_proj","o_proj"]`（`:67`）；Qwen2.5-1.5B：hidden 1536、28 层、12 heads / 2 KV heads、head_dim 128、r=16。

| 模块 | 形状 | LoRA 参数 |
|---|---|---|
| q_proj | 1536→1536 | 49,152 |
| k_proj | 1536→256 | 28,672 |
| v_proj | 1536→256 | 28,672 |
| o_proj | 1536→1536 | 49,152 |
| 单层合计 | | 155,648 |
| **28 层合计 P** | | **4,358,144** |

### 3.3 影响

| 阶段 | anchor 套数 | `param` 实际系数 | 相对 T2 |
|---|---|---|---|
| T2 | 2 | 2/P | 1× |
| T3 | 3 | 3/P | 1.5× |
| T4 | 4 | 4/P | 2× |
| T5 | 5 | 5/P | 2.5× |
| T6 | 6 | 6/P | 3× |

即 λ=100 在 T6 的实际强度是 T2 的 3 倍，**EWC 的遗忘曲线被阶段数污染**，与时间线 5 阶段结果不可直接比较。

### 3.4 修复方案

```python
# continual_training.py:585-589 替换
n_anchor = max(1, len(ewc_states))
if normalize in ("param", "mean") and per_state_param_count:
    total = total / (per_state_param_count * n_anchor)   # 每 anchor 每参数的平均
elif normalize == "task":
    total = total / n_anchor
```

配套：
- 新增 `normalize="mean"` 作为新默认（语义清晰），`param` 保留但标 deprecated（等价于 mean）。
- `compute_loss` 里分开记录 `ce_loss` / `ewc_penalty`：
  ```python
  self.log({"ce_loss": float(outputs.loss.detach()), "ewc_penalty": float(penalty.detach())})
  ```
- λ 必须在 **val** 上重搜：`--evaluate-split val --gate-current-acc`，换算 `λ_new ≈ λ_old / n_anchor`，起点可从 50 起，网格 `{0,10,25,50,100,250}`。

### 3.5 验证

- T2 日志中 `ewc_penalty / ce_loss` 应落在 `1e-2 ~ 1e0`；>10 说明 λ 过大（模型不学）。
- 报告必须同时出现 `ewc_anchor_sets` 与 `ewc_normalize`，便于复算。

### 3.6 兼容性

改 `_ewc_penalty` → `code_version` 变 → 全部 EWC 产物作废。**这就是必须先定方案再开跑的原因。**

## 4. P1-4 Fisher 在 fp16 下无 loss scaling

### 4.1 核对证据

```python
# continual_training.py:404-409
with torch.enable_grad():
    loss = model(**batch).loss
    loss.backward()
for name, parameter in parameters.items():
    if parameter.grad is not None:
        fisher[name].add_(parameter.grad.detach().float().cpu().square())
```

- 基座 bnb 计算精度固定 `torch.float16`（`:354`），评估侧同（`incremental_evaluation.py:341`）。
- 正式训练有 HF Trainer 的 GradScaler 兜底，**这里没有**：直接反传，小梯度在 fp16 下会下溢成 0。
- 在已拟合过的训练集上估经验 Fisher，本身偏小；叠加下溢 → **系统性低估** → EWC 惩罚偏弱 → 遗忘被低估。

### 4.2 影响

- 只影响 EWC。
- 方向与 P1-3 相反（一个偏强、一个偏弱），**两错可能相互抵消**，使 EWC 结果"看起来合理"却不可解释。

### 4.3 修复方案

**A（推荐，与 P2-4 一并做）：全流程 bf16**
- `bnb_4bit_compute_dtype=torch.bfloat16`（训练 `:354` + 评估 `:341` 两处）。
- `TrainingArguments(bf16=True, fp16=False)`。
- 4090D 原生支持 bf16，动态范围足够，不再需要 GradScaler。
- 代价：所有历史 fp16 结果不可与新结果混比，报告需注明。

**B（不换 dtype）：Fisher 显式 fp32**
```python
with torch.enable_grad(), torch.autocast(device_type="cuda", enabled=False):
    loss = model(**batch).loss
    loss.backward()
for name, p in parameters.items():
    if p.grad is not None:
        fisher[name].add_(p.grad.detach().float().square())
```

**C（兜底）**：`GradScaler` 包裹，`unscale_()` 后再取 `.grad`。

配套记录：`fisher_mean`、`fisher_zero_ratio` 写进状态文件与 `training_metadata.json`。

### 4.4 验证

- 期望 `fisher_zero_ratio < 0.5`；>0.8 说明仍在下溢。
- 取 50 条 T1 样本，在 fp32（CPU 或单卡 fp32）下重算一次 Fisher，与训练时记录对比量级。

### 4.5 兼容性

改 dtype → 指纹变 → 全部产物作废。**必须与 P1-3 一起决策，一次重训。**

### 5.4 修复方案

**方案 A（推荐，改动小）：采样按域分层轮转**

```python
def sample_by_domain(self, wanted: int, rng, n_domains: int) -> list[dict]:
    by_domain = defaultdict(list)
    for r in self.records:
        by_domain[str(r.get("task") or r.get("domain"))].append(r)
    quota = max(1, math.ceil(wanted / max(1, n_domains)))
    out = []
    for d in sorted(by_domain):
        bucket = by_domain[d]
        out += rng.sample(bucket, min(quota, len(bucket)))
    if len(out) < wanted:
        chosen = {id(x) for x in out}
        pool = [r for r in self.records if id(r) not in chosen]
        out += rng.sample(pool, min(wanted - len(out), len(pool)))
    return out[:wanted]
```

**方案 B（更彻底）：容量随阶段扩展**
- 每域每类 20 条：`capacity = 20 × 3 × n_seen`（T2=120 → T6=360）；或每域每类 40 条（T6=720）。
- 仍需与分层采样配合，否则容量大了但按类抽样依旧不公平。

**方案 C（不改代码，仅报告声明）**：在结果表注明"固定 300 容量、回放量随域数衰减"，并把每域回放条数写进 manifest。时间紧时这是可接受的。

### 5.5 验证

- 日志打印 `replay_per_domain_counts`（T6 应 ≥ 每域 40 条）。
- 单测：6 域 × 300 条假数据，跑 `update` + 分层 `sample`，断言每域 ≥ quota。

### 5.6 兼容性

方案 A 只改 `sample`；若把采样策略纳入指纹（新增 `replay_sample_policy`），否则新旧结果被判同配置。方案 B 改容量 → 指纹变 → Replay 从 T2 重跑。

### 8.2 判定：成立，且有 4 条可复现的坏路径

1. **已完成单元重跑（不加 `--skip-existing`）**：训练脚本抛 `FileExistsError` → 判 `conflict` → 默认 `archive` 把成品搬走并重训，**连共享 T1 也不例外**。

3. **"已完成 + `--resume`"**：先被 `archive` 搬走，重试时目录没了 → 若此前有 checkpoint 也被搬走 → `FileNotFoundError`，**等于把成品毁掉**。
4. **失败重试死循环**：第 1 次非 conflict 失败（如 OOM/未知）→ 无修复 → 目录残留 → 第 2 次撞 `FileExistsError` → 此时 `attempt >= attempts` 先 return，**根本没走修复分支** → 该方法 `stopped`。

### 8.3 影响

- 一次中断后的"正常重跑"会把已完成产物反复搬走、重训，浪费 GPU 小时且可能毁掉共享 T1。

### 10.1 核对证据

| 事实 | 位置 |

**核对**：EWC/Replay 先写状态文件（`continual_training.py:862-864`、`:869-879`），再写模型（`:886` → `:636`），最后写 `training_metadata.json`（`:655`）；`_save_ewc_state` 已存在即拒绝（`:505-506`）；`model_complete` 只看 `adapter_config.json`（`run_full_matrix.py:111-113`），非 EWC/replay 单元的 `training_unit_complete` 直接 `return True`（`:178`）。

**判定**：成立。两个具体后果：

1. 崩溃在"状态已写、模型未写"→ 下次训练因状态文件已存在而失败 → 只能靠 `archive` 修复，白跑一轮。
2. 崩溃在"模型已写、metadata 未写"→ `model_complete=True` + `training_unit_complete=True`（非 EWC）→ `--skip-existing` 直接跳过，留下**没有指纹的模型**，后续 `evaluation_result_matches` 因缺 metadata 永远 False（每次都重评）。

4. `_save_ewc_state` / `_save_replay_memory` 改为"存在则比对指纹：一致则复用、不一致才报错"，避免中断后必然失败。

## 16. Replay 恒定覆盖（B 方案）实现与口径

### 16.1 实现（三层同时改）

| 层 | 改动 | 效果 |
|---|---|---|
| 存储 | `ReplayMemory(mode="domain_class_balanced", per_domain=60)`：按 `(域 × 类)` 分桶，每桶 20 条 | 后续域不再挤占早期域的配额；T6 池内每域仍 60 条 |
| 采样 | `sample_per_domain(60)`：每域抽 60、域内按 N/R/W 各 20（A 作为实现细节） | 每域抽到条数与域数无关，且不会出现某域被抽空 |
| 预算 | 总抽样恒为 `NUM_EPOCHS × 600 = 1200`（300 步）；域间靠采样频率分配 | 与 sequential_ft / EWC 算力完全一致；每老域 60 条（10% 覆盖），剩余预算给新域 |

`--replay-per-domain 0` 可退回旧的定容模式（`capacity=300` + `ratio=3`），作为消融。

### 16.2 过境次数（Epochs）口径：等算力采样（默认 `equal_steps`）

固定总抽样 = `NUM_EPOCHS × 新域样本数 = 2 × 600 = 1200` 次（batch 4 → **300 步**，与 sequential_ft / EWC 完全一致）。预算分配顺序：先给每个老域各 60 条（1 遍），剩余全部给新域。

| 阶段 | 总抽样 | 步数 | 新域抽样 / 过境 | 每老域抽样 / 过境 |
|---|---|---|---|---|
| T2 | 1200 | 300 | 1140 / **1.90 遍** | 60 / 0.10 遍 |
| T3 | 1200 | 300 | 1080 / 1.80 遍 | 60 / 0.10 遍（×2 域） |
| T4 | 1200 | 300 | 1020 / 1.70 遍 | 60 / 0.10 遍（×3 域） |
| T5 | 1200 | 300 | 960 / 1.60 遍 | 60 / 0.10 遍（×4 域） |
| T6 | 1200 | 300 | 900 / **1.50 遍** | 60 / 0.10 遍（×5 域） |

- **总抽样与步数恒等于其它方法**，三组方法可以直接同表对比；
- 每个老域的覆盖恒为 10%（60/600），不随阶段衰减；
- 代价：新域过境从 1.90 遍降到 1.50 遍（因为固定预算里要切出一块给回放）。这是"等算力"的必然，报告中如实标注。

`training_metadata.json` 记录：`replay_policy`、`replay_per_domain`、`replay_sampling`、`replay_domain_counts`、`domain_draws`、`train_epochs`、`total_draws`、`steps_expected`、`passes_per_domain`。

> 若改用 `--replay-sampling equal_epochs`：每个被选中样本固定 2 遍，总抽样 1320→1800、步数 330→450，与其它方法算力不等，仅用于对照。

### 16.3 限制说明（C 口径，可直接写进论文/报告）

> 固定容量回放（fixed-size buffer）在持续学习文献中是标准设定，其定义性特征是**每个历史任务的回放覆盖率随任务数增加而下降**。本实验的主表采用"每域恒定配额（60 条/域，10% 覆盖）"以消除该衰减，使 Replay 的记忆强度与阶段数解耦，从而与 EWC 的归一化惩罚（`mean`，同样与 anchor 套数解耦）保持同一比较基准；作为对照，附录给出固定 300 容量 + 3:1 采样的标准设定结果，其 T6 每域覆盖率仅 6.7%，可用于说明"衰减是预算约束的必然结果，而非方法缺陷"。

## 附录 C：本文结论的可复核方式（全部离线，不占 GPU / 不调 API）

| 结论 | 复核方式 |
|---|---|
| 数据强/弱键均唯一、错域 0、年代分布 | 对 12 个 jsonl 计算 `"".join(text.split())` 与 `NFKC+casefold+去非文字` 两种键，比较唯一数；同时比对 `record["domain"]` 与 `TASKS[task]["domain"]` |
| 系统提示词 341 token、前缀 355 token、head 383 | 用本地 tokenizer 分别 encode `SYSTEM_PROMPT`、`apply_chat_template([system, user("待判断政策段落：\n")])`，再算 `767*0.5` |
| 截断 36/5,400、prompt 长度分布 | 对 5,400 条逐条渲染完整 prompt 并统计长度，与 767 比较 |
| LoRA 参数 4,358,144 | `28 层 × 16×(1536+1536) + 2×16×(1536+256) + 16×(1536+1536)`，按 q/k/v/o 各自形状 |
| P1-3 归一化线性增长 | 读 `_ewc_penalty` 求和与除法的先后顺序，代入 anchor 套数 2..6 |
| P1-8 四条坏路径 | 读 `run_with_retry` 的 `attempt >= attempts` 与 `repair_conflicts` 相对位置 |
| P2-7 共用目录 | 比对 `run_full_matrix.py:51-54` 与 `run_all_continual.py:36-37,96-97` 的路径常量 |
| P3 行号 | `Select-String -Pattern '1 到 5\|T1\.\.T4\|4 方法 × 5\|17 次\|60 组'` |

**注意**：做 tokenizer 统计时不要用 `apply_chat_template(..., tokenize=True)` 的返回值直接 `len()`——在部分 transformers 版本里它返回 dict（`len()` 恒为 2），会得出"截断率 0%"的错误结论。要用 `apply_chat_template(tokenize=False)` 再 `tokenizer(rendered)`。
